## 1.3 / 1.6 Where do the IDs in write calls come from?

For each write-call argument that references app data (`x-ref` in the catalog), look for its value in: (a) results of earlier calls in the same gold trajectory, (b) the history (assistant tool results), (c) nowhere.

| source of the ID | arguments | share |
|---|---|---|
| earlier read in same turn | 922 | 74.9% |
| history only | 308 | 25.0% |
| not found (known from context or guessed) | 1 | 0.1% |

Implication: when the ID is already in the history, the gold usually writes directly without reading again; a policy that always reads first loses precision on those samples.
Samples with history whose first gold call is a write: 339.
